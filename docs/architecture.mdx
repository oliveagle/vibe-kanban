# Architecture Overview

Vibe Kanban is a full-stack application built with **Rust** (backend) and **React + TypeScript** (frontend). This document provides a comprehensive overview of the project architecture, technology stack, and codebase organization.

## Rust Crates

### server

**Purpose**: Main API server, web routes, and MCP configuration

**Key Files**:
- `crates/server/src/main.rs` - Entry point, server initialization
- `crates/server/src/routes/` - API route handlers
  - `config.rs` - Configuration endpoints
  - `projects.rs` - Project CRUD
  - `tasks.rs` - Task management
  - `task_attempts.rs` - Task execution attempts (core execution logic)
  - `oauth.rs` - GitHub OAuth
  - `events.rs` - Server-sent events for real-time updates
  - `containers.rs` - Container/service management
  - `approvals.rs` - Approval workflows

### db

**Purpose**: SQLite database with SQLx, migrations, and data models

**Database**: SQLite with WAL mode, 120 second busy timeout

**Models** (`crates/db/src/models/`):
- `task.rs` - Task model with status (Todo, InProgress, InReview, Done, Cancelled)
- `project.rs` - Project grouping tasks
- `workspace.rs` - Execution workspace (git branch, container ref)
- `execution_process.rs` - Running agent processes
- `coding_agent_turn.rs` - Individual agent turns
- `session.rs` - Execution sessions
- `project_repo.rs` - Git repositories per project
- `workspace_repo.rs` - Repositories per workspace
- `merge.rs` - Merge operations
- `scratch.rs` - Scratch notes
- `tag.rs` - Task tags
- `image.rs` - Screenshots/images
- `execution_process_logs.rs` - Process output logs

### executors

**Purpose**: Abstractions and implementations for various AI coding agents

**Supported Agents**:
- Claude Code (Anthropic)
- Cursor AI editor
- GitHub Copilot
- OpenAI Codex
- Google Gemini CLI
- Amp
- Droid
- Qwen
- OpenCode

**Key Modules**:
- `profile.rs` - Executor profiles and configuration
- `command.rs` - Command execution
- `env.rs` - Environment variable handling
- `mcp_config.rs` - MCP server configuration
- `approvals.rs` - Approval handling

### services

**Purpose**: High-level business logic and orchestration

**Services**:
- `container.rs` - Main service container/aggregator
- `git.rs` - Git operations (worktrees, branches, commits)
- `github.rs` - GitHub API integration
- `events.rs` - Event streaming (SSE)
- `filesystem.rs` - File system operations
- `filesystem_watcher.rs` - File watching for changes
- `worktree_manager.rs` - Git worktree lifecycle
- `workspace_manager.rs` - Workspace management
- `project.rs` - Project operations
- `image.rs` - Image/screenshot handling
- `auth.rs` - Authentication
- `analytics.rs` - PostHog analytics
- `approvals.rs` - Approval workflows

### deployment

**Purpose**: Trait-based deployment abstraction for local vs cloud

**Deployment Trait** defines:
- Database access (`db()`)
- Service access (`git()`, `project()`, `container()`, etc.)
- Event streaming (`stream_events()`)
- Auto-project setup (`trigger_auto_project_setup()`)

### local-deployment

**Purpose**: Local deployment implementation (default for NPX)

Uses local SQLite and local process execution.

### remote

**Purpose**: Remote/cloud deployment with PostgreSQL and object storage

**Features**:
- PostgreSQL instead of SQLite
- S3/R2 compatible storage (AWS SDK)
- JWT authentication
- GitHub App integration
- Email notifications
- AES-GCM encryption

### utils

**Purpose**: Shared utilities

**Modules**:
- `assets.rs` - Asset directory management
- `diff.rs` - Diff generation
- `jwt.rs` - JWT handling
- `shell.rs` - Shell command execution
- `stream_lines.rs` - Stream line reading
- And more...

## Core Data Models

### Task

```rust
pub struct Task {
    pub id: i64,
    pub project_id: i64,
    pub title: String,
    pub description: Option<String>,
    pub status: TaskStatus,  // Todo, InProgress, InReview, Done, Cancelled
    pub parent_workspace_id: Option<i64>,  // For nested tasks
    pub shared_task_id: Option<String>,    // For shared/linked tasks
    pub created_at: DateTime<Utc>,
    pub updated_at: DateTime<Utc>,
}
```

### Workspace

```rust
pub struct Workspace {
    pub id: i64,
    pub task_id: i64,
    pub container_ref: Option<String>,
    pub branch: String,
    pub agent_working_dir: String,
    pub setup_completed_at: Option<DateTime<Utc>>,
    pub created_at: DateTime<Utc>,
    pub updated_at: DateTime<Utc>,
}
```

**Note**: Each task execution happens in a git worktree (isolated branch).

### ExecutionProcess

```rust
pub struct ExecutionProcess {
    pub id: i64,
    pub session_id: i64,
    pub status: ExecutionProcessStatus,  // running, completed, failed, killed
    pub run_reason: RunReason,  // setupscript, cleanupscript, codingagent
    // ...
}
```

### Session

Groups execution processes for a task attempt. Links workspace to execution.

### CodingAgentTurn

Individual turns within an execution with logs, diffs, and repo state snapshots.

## Architectural Patterns

| Pattern | Description |
|---------|-------------|
| **Workspace/Worktree** | Each task execution happens in a git worktree (isolated branch) |
| **Session/Attempt** | Tasks can have multiple attempts, each with multiple processes |
| **Executor Abstraction** | Pluggable executor pattern for different AI agents |
| **Service Container** | Central service container pattern for dependency injection |
| **Event Streaming** | Server-sent events (SSE) for real-time updates |
| **Deployment Abstraction** | Trait-based deployment allowing local vs cloud backends |
| **Type Generation** | Rust types automatically generate TypeScript definitions via ts-rs |

## Database Patterns

- **SQLite with WAL mode** for concurrent access
- **120 second busy timeout** to handle locks
- **SQLx with compile-time query verification** (via `prepare-db` script)
- **Migration-based schema management**
- **Models as active records** with static query methods

## Key Commands

```bash
# Development
pnpm run dev                 # Start frontend + backend (auto ports)
pnpm run backend:dev:watch   # Backend with cargo-watch
pnpm run frontend:dev        # Frontend dev server

# Type Generation
pnpm run generate-types      # Generate TS types from Rust

# Database
pnpm run prepare-db          # Prepare SQLx (offline mode)

# Testing
cargo test --workspace       # Run Rust tests
pnpm run check               # Type check frontend + backend

# Build
pnpm run build:npx           # Build NPX package
pnpm pack                    # (in npx-cli/) Pack NPX package
```
